# API — проектирование

Слоистая архитектура: `handler → service → repository (interface)`.
PostgreSQL (`pgx`) — единственное место записи (service layer). RabbitMQ —
side-effects (уведомления, аудит), не основной путь записи.

## 2. Общий формат ответов

**Успех — одиночный объект:**

```json
{ "data": { /* сущность */ } }
```

**Успех — список:**

```json
{ "data": [ /* Bullet[] */ ] }
```

**Ошибка:**

```json
{
  "data": null,
  "error": {
    "code": 400,
    "message": "title is required"
  }
}
```

`error.code` — числовой HTTP-статус (дублирует статус-код ответа),
отдельного строкового кода ошибки нет.

| Код | Когда |
| --- | --- |
| 200 | успешный GET/PUT/POST без создания ресурса |
| 201 | ресурс создан |
| 204 | успешное удаление, тело пустое |
| 400 | некорректный запрос (невалидный JSON) |
| 404 | ресурс не найден |
| 409 | конфликт (удаление непустой коллекции) |
| 422 | семантическая ошибка валидации |
| 500 | внутренняя ошибка |

## 3. Эндпоинты

### Health

**GET /health** → `200 { "status": "ok" }` — для Docker/orchestrator
healthcheck.

### Bullets

#### POST /api/bullets

**Юзкейс**: пользователь записывает новую задачу в сегодняшний список
— как строчку в бумажном bullet journal.

- **Актор**: пользователь
- **Предусловие**: нет (bullet создаётся с нуля)
- **Основной поток**: `title` не пустой → создаётся bullet со
  `status = OPEN`
- **Ошибка**: `title` пустой/невалидный → `400`

```json
// request
{
  "collection_id": "uuid", "title": "Оплатить хостинг"
}
```

```json
// response 201
{
  "data": {
    "id": "uuid",
    "collection_id": "uuid",
    "title": "Оплатить хостинг",
    "status": "OPEN",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

```json
// response 400
{
  "data": null,
  "error": {
    "code": 400,
    "message": "title is required"
  }
}
```

#### GET /api/bullets?collection_id=

**Юзкейс**: пользователь просматривает свои задачи, сгруппированные
по дням — как разворот страниц в bullet journal.

- **Актор**: пользователь
- **Предусловие**: нет (список может быть пустым)
- **Основной поток**: bullets группируются по календарному дню
  `created_at`
- **Альтернативный поток**: bullets отсутствуют → `200` с пустым
  списком групп (`"data": []`), не `null`

- `collection_id` — фильтр по коллекции (опционально)

Ответ группирует bullets по календарному дню (`created_at`, дата без
времени): группы отсортированы от нового дня к старому, а bullets
внутри группы — от старого к новому (новые снизу).

```json
// response 200
{
  "data": [
    {
      "day": "2026-07-28",
      "bullets": [ /* Bullet[] */ ]
    }
  ]
}
```

#### POST /api/bullets/{id}/done

**Юзкейс**: пользователь отмечает задачу выполненной, не удаляя её —
как галочка в бумажном bullet journal.

- **Актор**: пользователь
- **Предусловие**: bullet с данным `id` существует
- **Основной поток**: bullet имеет `status = OPEN` → переводится в
  `DONE`
- **Альтернативный поток**: bullet уже `DONE` → `200` без изменений
  (идемпотентность)
- **Ошибка**: bullet с данным `id` не найден → `404`

Логика: `status` bullet переводится в `DONE`, запись не удаляется —
удалить её пользователь может отдельно через `DELETE`. Идемпотентно:
если bullet уже `DONE`, повторный вызов — `200` без изменений.

```json
// response 200
{
  "data": {
    "id": "uuid",
    "title": "Оплатить хостинг",
    "status": "DONE",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

```json
// response 404
{
  "data": null,
  "error": {
    "code": 404,
    "message": "bullet not found"
  }
}
```

### Collections

> Реализация отложена: сначала MVP на `Bullet`, `Collection`
> подключается позже.

#### POST /api/collections

**Юзкейс**: пользователь заводит новую коллекцию — тематический
список, в который потом будут попадать bullets, как открыть новый
раздел в bullet journal.

- **Актор**: пользователь
- **Предусловие**: нет (коллекция создаётся с нуля)
- **Основной поток**: `topic` не пустой → создаётся коллекция
- **Ошибка**: `topic` пустой/невалидный → `400`

```json
// request
{ "topic": "Идеи для проекта" }
```

```json
// response 201
{
  "data": {
    "id": "uuid",
    "topic": "Идеи для проекта",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

#### GET /api/collections

**Юзкейс**: пользователь просматривает список своих коллекций, чтобы
выбрать, в какую добавлять bullets.

- **Актор**: пользователь
- **Предусловие**: нет (список может быть пустым)
- **Основной поток**: возвращается список коллекций
- **Альтернативный поток**: коллекций нет → `200` с пустым списком
  (`"data": []`), не `null`

```json
// response 200
{ "data": [ /* Collection[] */ ] }
```

#### GET /api/collections/{id}

**Юзкейс**: пользователь открывает конкретную коллекцию.

- **Актор**: пользователь
- **Предусловие**: коллекция с данным `id` существует
- **Основной поток**: возвращается коллекция
- **Ошибка**: коллекция с данным `id` не найдена → `404`

```json
// response 200
{
  "data": {
    "id": "uuid",
    "topic": "Идеи для проекта",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

```json
// response 404
{
  "data": null,
  "error": {
    "code": 404,
    "message": "collection not found"
  }
}
```

#### PUT /api/collections/{id}

**Юзкейс**: пользователь переименовывает коллекцию.

- **Актор**: пользователь
- **Предусловие**: коллекция с данным `id` существует
- **Основной поток**: `topic` не пустой → коллекция обновляется
- **Ошибка**: коллекция не найдена → `404`; `topic` пустой/невалидный
  → `400`

```json
// request — полная замена
{ "topic": "Идеи для проекта" }
```

```json
// response 200
{
  "data": {
    "id": "uuid",
    "topic": "Идеи для проекта",
    "created_at": "...",
    "updated_at": "..."
  }
}
```

```json
// response 404
{
  "data": null,
  "error": {
    "code": 404,
    "message": "collection not found"
  }
}
```

```json
// response 400
{
  "data": null,
  "error": {
    "code": 400,
    "message": "topic is required"
  }
}
```
